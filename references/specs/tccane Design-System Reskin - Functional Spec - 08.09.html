Functional Specification

tccane Website — Tzu Chi USA Design-System Reskin

Re-skin the tccane-website-v2 front-end to the Tzu Chi USA design system — the emerald-led, section-coded palette plus the PT Serif / Lato type system — preserving all existing layout, content, icons and motif shapes, with every text/background pairing meeting WCAG AA. Delivered in an isolated git worktree.

Date: 2026-08-09  ·  Status: Approved for design/build  ·  Sources used: tc-us-design-system/tzu-chi-design-guidelines.md, tc-us-design-system/examples/tzu-chi-design-system.html, tccane-website-v2/styles.css, tccane-website-v2/index.html, references/_source/extracted/_ds/…/tokens/{colors,fonts}.css, tccane-website-v2/tests/*, package.json

1 · Goal

Purpose

The current site is styled to a navy-primary palette that was derived from imagery before an official reference existed (styles.css:17 --tc-navy:#1B2A4A; the extracted token pack even labels itself "derived, approximate… no official Tzu Chi palette exists"). The Tzu Chi USA 2024 Annual Report establishes an authoritative visual language that is green-led and section-coded, and the design guidelines explicitly state this "supersedes the navy-primary assumption" (tzu-chi-design-guidelines.md:43). This project brings the tccane site into line with that official language on color and typography, without disturbing the layout, content, or the icon/motif set the team likes.

Success criteria (observable)

  • Palette matches source. Emerald #006A41 leads as primary; blue #0872B9 and periwinkle #6B6EB3 serve as mission accents; white-dominant surfaces with pale mint/sky/lavender tints — per tzu-chi-design-guidelines.md:45–60. No navy remains as an interface primary.
  • Type matches source. PT Serif carries display + body; Lato carries labels/eyebrows/UI (tzu-chi-design-guidelines.md:123–128), and the real typefaces actually render for visitors (not silent fallback).
  • Accessibility is a hard gate. Every text/background pairing measures ≥ WCAG AA (4.5:1 body, 3:1 large text / meaningful graphics), using the -deep accent variants on tints where required (tzu-chi-design-guidelines.md:112–121).
  • Structure preserved. No change to information architecture, section order, copy, or layout. Sections about · why · missions · life · chapters · resources · involved remain (index.html anchors).
  • Motifs preserved in form, updated in color. All illustrations/icons keep their shapes; their colors follow the new palette (the report shows the lotus mark as green — tzu-chi-design-guidelines.md:170).
  • No regressions. The 13 existing vitest suites stay green and the Cloudflare Pages build still serves (package.json test: vitest run; pages:dev via wrangler).

Non-goals

  • No layout, IA, section-order, or component-structure changes.
  • No copy/content changes.
  • No new features or new pages.
  • No redrawing or replacing icons/motifs (shape is frozen; only color follows the palette).
  • No spacing, radius, or motion overhaul (motion stays as-is; the DS's restraint guidance is already satisfied).
  • No backend/Functions changes (interest form, Google Sheets, Turnstile, rate-limit logic untouched).

Hard constraints

  • Work happens in an isolated git worktree off tccane-website-v2, not the main checkout.
  • WCAG AA is enforced, not best-effort.
  • Existing tests must stay green; Cloudflare Pages deploy must keep working.
  • Self-hosted assets only for fonts — external font CDNs are excluded (aligns with the project's web security/CSP and performance rules).

Naming-collision watch. The --tc- prefix is shared by both systems, but three token names mean different things: current --tc-sky is a mid-blue accent (#4A78B0) whereas the DS --tc-sky is a pale medical tint (#ECF4F8); likewise --tc-grey (#6E7277 vs #6B6660) and the reuse of --tc-white. A naive paste of the DS :root block over the current one would silently corrupt semantics — the chosen token strategy (Fork A) must handle this deliberately.

3 · Decision tree / approaches

Fork A — Token application strategy Chosen: Repoint existing semantics

At stake: How the new palette lands on top of the existing, well-structured --tc-* token layer — and how much downstream CSS is disturbed (regression risk vs. alignment with DS docs).

Repoint existing semantics Recommended · Chosen

Keep every semantic token name (--tc-text-strong, --tc-action, --tc-surface-*) and all component CSS untouched. Replace the primitive block (styles.css:15–30) with emerald-led values, add the DS tints (mint/sky/lavender) as new primitives, and resolve the three name collisions explicitly. Because inline styles and the semantic layer already point at these tokens, the recolor propagates automatically.

Trade-off: Lowest churn and lowest regression risk; preserves layout exactly. Cost: the internal vocabulary stays tccane's, not a 1:1 mirror of the DS doc names.

Adopt DS vocabulary wholesale Rejected

Introduce --tc-emerald/--accent/--tint/--section-accent and rewrite component references to match the DS docs. Cleaner conceptual mapping, but touches far more CSS across the file and raises regression risk against a "no layout change" goal.

Hybrid: repoint + parallel DS layer Rejected

Repoint semantics and layer in --accent/--tint/data-accent hooks. More flexible, but maintains two naming systems in one file — unnecessary complexity for the scope (YAGNI). The one place that genuinely needs accent-switching (Fork B) is handled with a minimal, contained hook instead.

User choice: → Repoint existing semantics. Rejected: DS-vocabulary rewrite; full hybrid layer.

Fork B — Section-coding depth Chosen: Emerald-led + code #missions only

At stake: The DS's signature is one accent per mission (emerald/blue/periwinkle), with "one accent per section, never mixed within a spread" (tzu-chi-design-guidelines.md:110). The tccane site has exactly one mission-structured section (#missions); the rest (about, why, life, chapters, resources, involved) are not missions.

Emerald-led globally + section-code #missions only Recommended · Chosen

Emerald is the single primary across the page. Inside #missions, apply per-mission accents (Charity/Education → emerald, Medical → blue, Global → periwinkle) via a contained data-accent hook that drives --section-accent/--section-tint. Honors the DS's defining device exactly where missions actually appear; nowhere is a hue assigned arbitrarily.

Trade-off: Faithful and restrained. Cost: a small amount of net-new CSS for the accent hook (the current CSS has no data-section today).

Single emerald everywhere Rejected

One emerald accent, no per-mission hues. Simplest and fully "green leads," but discards the section-coded richness that is the report's most recognizable trait — under-delivers on brand fidelity for very little saved effort.

Full section-coding, all page sections Rejected

Assign mission hues to every section. Off-spec: non-mission sections have no mission to map to, so hue choice becomes arbitrary and risks "mixing hues within a spread." Also nudges toward implied IA meaning the content doesn't carry.

User choice: → Emerald-led + code #missions only. Rejected: single emerald; full section-coding.

Fork C — Font loading for PT Serif + Lato Chosen: Self-host woff2 + preload

At stake: PT Serif and Lato are not installed on most machines, and the site loads no web fonts today (index.html:9 links only styles.css + favicon). Even the DS's own demo declares family stacks and loads nothing (examples/…html:29–30) — so "adopt PT Serif + Lato" is meaningless without a loading decision.

Self-host subset woff2 + preload critical weight Recommended · Chosen

Ship subset PT Serif and Lato woff2 files locally, declared via @font-face with font-display: swap, preloading only the critical weight/style. Delivers true typographic fidelity and satisfies the project's self-host/CSP security posture and performance budget.

Trade-off: Adds a modest font payload and a small set of binary assets to manage/subset. This is the only option that makes the type goal observably true for real visitors.

Family stacks only, no web fonts Rejected

Match the DS demo exactly (stacks + Georgia/system fallback, load nothing). Zero payload and fully self-contained, but most visitors would never see PT Serif/Lato — failing the "type matches source" success criterion.

Google Fonts CDN Rejected

Load from fonts.googleapis.com. Faithful and easy, but an external origin conflicts with the project's web security (CSP / prefer-self-host) and performance rules.

User choice: → Self-host woff2 + preload. Rejected: stacks-only; Google CDN.

Fork D — Worktree setup Chosen: Sibling worktree, feat branch, npm ci

At stake: Isolation of the reskin from the main working tree, and whether the worktree can actually run the checks that gate "no regressions." node_modules is gitignored, so a worktree starts without dependencies.

Sibling worktree on a feature branch, npm ci inside it Recommended · Chosen

Create a git worktree at ../tccane-website-v2-reskin on branch feat/tc-us-design-reskin; run npm ci in it so vitest and wrangler pages dev work. Leave the superseded references/_ds extraction in place as historical record.

Trade-off: Clean isolation; the checks that prove the success criteria run in the same place the work happens. Cost: a second dependency install on disk.

In-repo .worktrees/ + refresh extracted tokens Rejected

Worktree under a gitignored .worktrees/reskin, and additionally rewrite the superseded references/_source/_ds token files to the new palette. Rewriting the historical extraction expands scope beyond the site itself and risks re-implying it is authoritative; left as an optional follow-up instead.

Branch only, no worktree Rejected

Work directly on a feature branch in the main checkout. Simpler, but no isolation — contrary to the original request.

User choice: → Sibling worktree + feature branch + npm ci. Rejected: in-repo worktree with token refresh; branch-only.

5 · Desired end-state

What exists when this is done

  • A git worktree at ../tccane-website-v2-reskin on feat/tc-us-design-reskin with dependencies installed, tests passing, and the site serving locally via wrangler.
  • styles.css primitives redefined to the Tzu Chi USA palette (emerald primary; blue/periwinkle accents; mint/sky/lavender tints; warm near-black ink; warm grey), with the three name collisions resolved so the existing semantic layer resolves correctly. Navy no longer functions as an interface primary.
  • A contained data-accent hook applied within #missions that recolors each mission to emerald / blue / periwinkle and its matching tint, following the DS section-coding rules.
  • PT Serif and Lato self-hosted (subset woff2, font-display: swap, critical weight preloaded), wired through the existing typography tokens (styles.css:68–73) so display/body render in PT Serif and labels/eyebrows in Lato.
  • Motif and icon SVGs unchanged in shape; their previously hardcoded navy hex updated to the new palette (or converted to currentColor where appropriate) so nothing clashes on an emerald page.
  • The stray #ffe3e3 at styles.css:843 and any other escaped colors folded into tokens.

How success is observed

  • Visual pass at 320 / 768 / 1024 / 1440 shows an emerald-led, white-dominant site with mission accents in #missions, and the real PT Serif/Lato faces rendering.
  • A contrast check confirms every text/background pairing meets AA, with -deep variants used on tints where required.
  • vitest run is green (13 suites) and wrangler pages dev serves the reskinned site without console errors.
  • Layout, section order, copy, and motif shapes are visibly identical to the pre-reskin site.

Explicitly out of scope (remainder)

  • Any IA, layout, spacing, motion, copy, or feature change.
  • Redrawing/replacing icons or motifs.
  • Backend/Functions, interest-form, Google Sheets, Turnstile, or rate-limit logic.
  • Rewriting the superseded references/_source/_ds extraction (optional future cleanup).
  • Dark mode or any second theme (the DS commits to a single light world by design).
