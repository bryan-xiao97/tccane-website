Final result: The Cloudflare-hosted interest form now initializes Turnstile and submits successfully to the Google Sheets-backed production flow, confirmed directly by the user.

Determine why the production interest form reported that it was temporarily unavailable, decide whether the fault was in infrastructure or application code and restore the complete submission path.

What worked

  • Tracing the visible error through app.js, interest-form.js and functions/api/config.js tied the symptom to a precise runtime condition.
  • Direct HTTP probes separated GitHub Pages static hosting from Cloudflare Pages Functions behavior.
  • Passing all 113 tests helped rule out a broad application-code regression.
  • Comparing immutable deployment URLs, commit hashes and the stable production alias isolated the deployment regression.
  • Explicitly tailing deployment 007c3ba0 captured the decisive google_auth_permanent / invalid_client event.
  • The investigation progressed layer by layer: initialization, Cloudflare configuration, deployment routing, Turnstile, Google OAuth and Sheets delivery.
  • The user's final confirmation provided direct evidence that the full production flow worked.

Session summary

The initial unavailable message came from missing Turnstile configuration in the deployed Cloudflare environment, not from the form's core logic. A committed Wrangler configuration overrode the first dashboard-only correction, then retrying an older deployment briefly restored the failure. After the correct production deployment was activated, live Function logs revealed a second independent fault: Google rejected the OAuth client credentials with invalid_client. Rotating and updating the matching OAuth credentials completed the recovery, and the user confirmed that the form works.
