What worked

  • A failing regression test reproduced submission while configuration was pending before the browser code changed.
  • Attaching the handler synchronously removed the native-navigation race and kept the page stable during setup.
  • Live endpoint and deployment inspection exposed the difference between the working tree, failed preview and old production deployment.
  • Replacing the runtime OAuth library with a native fetch token exchange removed the bundle blocker while preserving the library for the one-time local owner setup.
  • The investigation separated application code, deploy-command configuration and token authorization instead of treating them as one failure.
  • Local Pages checks verified that /api/config serves JSON and the browser module is served as JavaScript.

Session summary

The apparent page refresh began as a real client-side timing bug, but fixing that race did not make the feature live. The production site was an older commit and the feature preview had failed. A Node-oriented OAuth dependency blocked the Pages Functions bundle, the dashboard used the wrong Wrangler deploy command and the custom token lacked Pages permission. The repository now passes 113 tests, compiles as Pages Functions without an explicit compatibility flag and serves the expected local endpoint types. The remaining work is to commit and deploy, verify the corrected Cloudflare settings and complete one real browser-to-Sheets acceptance test.
